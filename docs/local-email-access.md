# Локальная почта и защищённый доступ с телефона

Инструкция относится к локальным регистрации, входу и восстановлению [E009](implementation/epics/e009-email-access/README.md).
Внешние SMTP, провайдеры и развёртывание здесь не используются.

## Запуск на машине разработки

Из корня репозитория:

```powershell
Copy-Item .env.example .env
npm ci
docker compose up -d --wait postgres mailpit
npm run db:generate
npm run db:migrate
npm run dev
```

Откройте <http://127.0.0.1:5173/diary> и нажмите «Создать дневник». Введите имя, синтетический адрес и пароль
от 12 до 256 символов. Почта нормализуется удалением пробелов по краям и приведением
регистра; точки и `+` остаются. Mailpit принимает любой тестовый адрес без внешней доставки.
Письма находятся на <http://127.0.0.1:8025>; приложение на хосте использует SMTP
`127.0.0.1:1025`, в Compose — `mailpit:1025`. Оба опубликованных порта Mailpit
привязаны к loopback. Для собранного сервера задайте в `.env`
`APP_ORIGIN=http://127.0.0.1:3000` и выполните `npm run build`, `npm start`.

`APP_ORIGIN` определяет допустимый Origin и адрес ссылок писем. Он не берётся из Host.
Запрос письма ещё не создаёт атлета. Ссылка открывает страницу подтверждения;
только кнопка «Подтвердить почту» выполняет защищённый POST и создаёт один дневник.
Не меняйте origin между отправкой и подтверждением. Калькулятор не запрашивает сессию.

Для повторного входа откройте дневник и введите подтверждённую почту и прежний пароль.
Повторная регистрация занятого адреса не меняет доступ и предлагает войти в прежний
дневник. Восстановление пароля реализуется отдельно в E009-T003.

## Восстановление доступа

Для восстановления выберите «Забыли пароль», укажите почту и откройте письмо
в Mailpit. Принятие запроса не гарантирует доставку и не раскрывает наличие дневника.
Неизвестная почта письма не получает; SMTP-отказ не меняет доступ. Если письма нет,
повторите запрос позже. При недоступности Mailpit проверьте `docker compose ps`;
служба использует `MP_SMTP_DISABLE_RDNS=true`, чтобы обратный DNS не задерживал SMTP.
Ссылка восстановления действует 30 минут. Только «Установить пароль» меняет пароль,
сохраняя дневник и записи; затем войдите обычным способом с новым паролем.
Все прежние сессии и ссылки восстановления после смены отзываются.
Отмена ожидающего запроса аннулирует его ссылку; отмена формы нового пароля
не меняет доступ. Без почты или подключённого способа автоматическое восстановление
не обещается. Первый пароль аккаунта внешнего провайдера здесь не реализован.

## Локальный HTTPS для телефона

Телефон и машина разработки должны находиться в одной доверенной локальной сети.
Выберите постоянный на время проверки LAN-адрес машины, например `192.168.1.10`.
HTTP по LAN не подходит: для Web Crypto и защищённой cookie нужен доверенный HTTPS.

Установите [mkcert](https://github.com/FiloSottile/mkcert#installation) по инструкции
для своей ОС. Команды выполняются локально, публичный домен и внешний TLS не нужны:

```powershell
New-Item -ItemType Directory -Force .local-certs
mkcert -install
mkcert -cert-file .local-certs/app.pem -key-file .local-certs/app-key.pem 192.168.1.10 localhost 127.0.0.1 ::1
mkcert -CAROOT
```

Установите на телефон **только** `rootCA.pem` из показанного каталога как доверенный
корневой сертификат. `rootCA-key.pem` остаётся на машине разработки. На iOS после
установки профиля включите полное доверие сертификату в настройках сертификатов.
На Android установите CA для приложений/браузера в настройках безопасности; названия
пунктов зависят от версии ОС. После проверки можно удалить установленный CA с телефона.
Ключи и `.local-certs` исключены из git. Не передавайте приватный ключ CA на телефон.

В `.env` задайте:

```dotenv
APP_ORIGIN=https://192.168.1.10:5173
LOCAL_HTTPS_HOST=192.168.1.10
LOCAL_HTTPS_CERT=.local-certs/app.pem
LOCAL_HTTPS_KEY=.local-certs/app-key.pem
SMTP_HOST=127.0.0.1
SMTP_PORT=1025
```

Перезапустите `npm run dev`. Vite слушает выбранный адрес по HTTPS и передаёт `/api`
в NestJS на loopback. Это единый origin приложения и API. NestJS, PostgreSQL, SMTP
и интерфейс Mailpit не публикуются в LAN. При необходимости разрешите входящий
TCP 5173 только для доверенной частной сети в локальном firewall. Не используйте
переход мимо предупреждения о сертификате как успешную проверку доверия.
Ошибка чтения сертификата не переключает Vite на HTTP.

Откройте на телефоне `https://192.168.1.10:5173/diary`. Письмо читайте в интерфейсе
Mailpit на машине разработки; передайте на телефон ссылку с тем же HTTPS origin.
Не пересылайте письмо во внешний почтовый сервис. Фрагмент с токеном удаляется
из адресной строки при показе страницы. Без явного подтверждения дневник не создаётся.

## Приёмка на устройстве

Для Safari iOS и Chrome Android проверить:

- HTTPS открывается без предупреждения и сертификат имеет доверенную локальную CA.
- `/api/health` доступен через тот же origin; чужой Origin и запрос без CSRF получают отказ.
- Ввести имя, почту и пароль, увидеть письмо в Mailpit. До кнопки подтверждения
  дневник отсутствует; после неё пустой дневник открывается и переживает перезагрузку.
- Через инструменты браузера убедиться: cookie называется `__Host-session`, имеет
  Secure, HttpOnly, SameSite=Lax, Path=/ и не имеет Domain. JavaScript не читает её.
- В консоли браузера `window.isSecureContext` и `Boolean(crypto.subtle)` дают `true`;
  создание и закрытие тестовой IndexedDB завершаются без ошибки. Для полной проверки
  шифрования и записи использовать существующий сценарий черновиков E005.
- Проверить настоящую русскую клавиатуру, менеджер паролей, масштабирование текста,
  доступность кнопок и отсутствие горизонтальной прокрутки.
- Отменить ожидающую регистрацию, повторить ссылку, запросить новое письмо,
  проверить истечение и отказ канала по автоматическим сценариям ниже.

Настройка HTTPS и эмуляция Chromium не подтверждают доверие на физическом телефоне.
Оставшиеся проверки фиксируются в [приёмке E009](implementation/epics/e009-email-access/acceptance.md).

## Автоматические проверки

```powershell
docker compose up -d --wait postgres mailpit
$env:TEST_DATABASE_URL='postgresql://kachok:local-only-password@127.0.0.1:54329/kachok_local'
npm run build
node --test tests/email-registration.test.mjs tests/password-login.test.mjs tests/password-recovery.test.mjs
npm test
```

Для другого изолированного экземпляра Mailpit задайте `TEST_SMTP_PORT` и
`TEST_MAILPIT_URL`; по умолчанию используются 1025 и `http://127.0.0.1:8025`.
Тесты создают отдельные синтетические БД, адреса с UUID и не удаляют чужие письма.
Полный запуск чистого снимка `npm run check` сам поднимает PostgreSQL и Mailpit
на случайных loopback-портах и передаёт эти параметры тестам.

Регистрация проверяет Argon2id (64 MiB, 3 прохода, 4 линии, индивидуальная соль 16 байт),
срок токена 24 часа, назначение, одноразовость, отмену, повторную отправку,
конкурентные подтверждения одной и разных ссылок, Origin/CSRF, cookie и SMTP-отказ.
Используется асинхронный Argon2id из [Node.js 24](https://nodejs.org/docs/latest-v24.x/api/crypto.html#cryptoargon2algorithm-parameters-callback);
его API пока экспериментальный, поэтому стоимость и формат хеша зафиксированы и покрыты тестом.

Временная попытка браузера живёт 30 минут. Лимиты в PostgreSQL: 60 попыток формы
за 15 минут на IP, 30 запросов писем в час на IP, 5 в час на хеш нормализованной
почты, 30 подтверждений за 15 минут на IP. Vite передаёт API через loopback,
поэтому разные телефоны делят IP-лимит машины разработки. X-Forwarded-For не доверяется.
После истечения доказательства формы первое действие получает отказ до изменения
данных; следующая явная попытка обновляет доказательство без автоматического повтора
POST. Для повторного письма после истечения исходной попытки можно заново указать почту.
После лимита дождитесь следующего окна.
Сессия хранится хешем в БД, действует не более 90 суток и 30 суток без активности.

При ошибке доставки проверьте `docker compose ps`, доступность локального Mailpit
и значения SMTP. Не добавляйте SMTP debug и тела запросов в журналы: они содержат
почту, пароль или токены. Сбой отправки регистрации отменяет непригодное ожидание;
в восстановлении фиксируется отдельный отказ доставки без изменения пароля. Новый запрос разрешён
в пределах лимитов. При неуспешной повторной отправке прежнее доставленное письмо остаётся пригодным.
В Compose отключён обратный DNS SMTP-клиента: в изолированной сети Docker lookup
может задерживать приветствие сервера и приводить к тайм-ауту отправки.
