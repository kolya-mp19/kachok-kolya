# Навигация по задачам E002–E030

Согласованная разбивка опубликована отдельными файлами задач по скиллу `to-tickets`.
Карточки эпиков содержат реестры задач, критерии и зависимости находятся в самих задачах.
Восемь задач [E001](../epics/e001-technical-design/README.md) сохранены.

## Задачи

Для E002–E030 созданы 116 задач; с учётом E001 — 124 задачи.

1. [E002–E010: проектирование, основа, калькулятор и вход](./e002-e010.md) — 37 задач.
2. [E011–E020: изоляция, упражнения, планирование и запись тренировки](./e011-e020.md) — 40 задач.
3. [E021–E030: МПВ, подсказки, показатели, аналитика и выпуск](./e021-e030.md) — 39 задач.

В каждой группе приведены ссылки на карточки эпиков и отдельные задачи.
Критерии приёмки PRD без собственных идентификаторов отсчитываются по порядку
чекбоксов; это обозначения покрытия в задачах, исходные PRD не меняются.

## Условия детализации

Задачи S01 дают проектные решения и документацию. Разбивка следующих шагов условна
до получения согласованных результатов S01: выбранные технологии и конкретные
проверки нужно перенести в зависимые PRD и уточнить перед исполнением.
Подготовка задач не означает согласования стека или разрешения создавать проект.

Открытые продуктовые вопросы остаются в бизнес-требованиях:

- [PLAN-Q1](../../requirements/week-planning/open-questions.md) блокирует сравнение
  подозрительного ввода с историей в E016, но не весь ручной ввод.
- [PROGRESS-Q1](../../requirements/progress-analytics/open-questions.md) блокирует
  приёмку совпадающих дат собственного веса в E025/E027.
- [Условие удаления аккаунта](../../backlog.md) проверяется при согласовании аудитории
  и перед доступом первого незнакомого атлета. Поток удаления уточняется в требованиях
  при применимости этого условия.

## Продолжение

Выполнение задач не начато. Следующее действие общего плана —
[E001-T001](../epics/e001-technical-design/tasks/t001-constraints.md).
Состояние задач ведётся только в карточках эпиков; сначала выполняются задачи,
чьи необходимые входы получены и блокеры сняты.
