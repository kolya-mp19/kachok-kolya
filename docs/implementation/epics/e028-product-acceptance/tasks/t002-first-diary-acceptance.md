# E028-T002. Принять первый дневник и повторное ручное планирование

## Что сделать

Доказательство основного полезного пути без МПВ, включая повторное планирование на телефоне.

Проверяется конкретная сборка в согласованных условиях; результаты связываются с требованиями и воспроизводимыми примерами. Подготовка задачи не является разрешением на реальные операции выпуска или отправку приглашений.

Перед выполнением согласованные решения [S01](../../../README.md) должны быть перенесены в PRD; технологии и конкретные проверки уточняются по этим решениям. Подготовка задач не означает согласования технологического стека или начала реализации.

Все проверочные срезы используют идентифицированную сборку, воспроизводимые данные и
независимые ожидаемые результаты. Подготовка матрицы может начаться заранее;
выполнение сценария ждёт перечисленных работающих входов и согласованной мобильной среды
[E002](../../e002-mobile-experience/prd.md)/[E003](../../e003-release-design/prd.md).

**Заблокирована:** [E009](../../e009-email-access/prd.md), [E014](../../e014-gyms-and-selection/prd.md), [E017](../../e017-plan-management/prd.md), [E019](../../e019-workout-recording/prd.md) — регистрация, выбор и создание из ввода, план/разминка/факт; [E020-T001](../../e020-workout-history/tasks/t001-workout-and-exercise-history.md) — работающая история упражнения рядом с вводом веса.

## Критерии готовности

- [ ] Первый цикл, упражнение/зал из ввода, нотация и пошаговый ввод с клавиатурой, история у веса и отметка подхода одним касанием проходят
- [ ] При повторном планировании история у поля веса показывает реальные сохранённые план и факт предыдущего выполнения того же атлета; проверочный источник вместо интеграции E020-T001 не используется. Отсутствие истории не блокирует первый ручной план.
- [ ] Копирование в пустое будущее не копирует веса
- [ ] Первый подход/конец недели/прерывание фиксируют план, снятие факта не открывает его
- [ ] Отдельная разминка план не фиксирует.

## Проверка

Пройти описанный сценарий по критериям готовности и сверить наблюдаемый результат с [PRD эпика](../prd.md). Проверить допустимые и недопустимые входы, границы исправлений и сохранность исходных записей там, где они затронуты.

Покрытие приёмки эпика: пункты 1–3, 8 (в своей области).

В этом PRD «пункт N» означает позицию чекбокса в разделе приёмки, считая сверху с единицы; новая нумерация в PRD не вводится.

## Результат и продолжение

Результат ещё не подготовлен. Состояние задачи ведётся только в реестре [карточки эпика](../README.md). При выполнении зафиксировать проверенный результат; перед остановкой обновить там текущую точку и конкретное следующее действие.
