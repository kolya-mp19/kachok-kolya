# E007-T004. Сохранять корректный рейтинг на ничьих и краях диапазона

## Что сделать

**Что даёт:** общий рейтинг всех формул устойчив к близким итогам, неполным карточкам и необычным допустимым значениям.

Согласованные решения S01 перенесены в [PRD](../prd.md); локальные E004, E005 и
E006-T001 приняты. T002/T003 предоставили все три формулы с проверенными
первоисточниками и независимыми эталонами обоих полов. Общая приёмка выполняется
через публичную границу ядра TypeScript независимо от интерфейса и данных дневника.
Внешние E003 и E006-T002/T003 не блокируют локальное исполнение;
внешние интеграции и выпуск отложены.

Локальных блокеров нет. Источник статуса — реестр задач в карточке эпика.

## Критерии готовности

- [x] Для каждого пола и формулы проверены малый/большой положительный собственный вес, конечный отрицательный коэффициент, резкий рост и неконечность без новых ограничений ввода.
- [x] Примеры `40; 40; 39` и `40.004; 40.003` дают соответственно `1; 1; 3` с двумя лидерами и `1; 2` с одним; коэффициент перед умножением не округляется.
- [x] Равные строки и строки без итога сохраняют порядок добавления; последние идут после ранжируемых без места, при отсутствии итогов нет лидеров.
- [x] Выходной контракт и контрольные примеры переданы E008, короткие подписи не меняют места.

Отрицательность, резкий рост и неконечность проверяются там, где математически
возможны. У мужского IPF GL коэффициент положителен и меньше `0.573` при любом
положительном собственном весе; отрицательного или неконечного итога для допустимой
конечной попытки не существует. Его проверка подтверждает положительность,
конечность и ограниченность на краях, без искусственного отказа или изменения формулы.

## Проверка

[25 приёмочных тестов](../../../../../tests/calculator-ranking.test.mjs)
запускаются через `node --test tests/calculator-ranking.test.mjs`.
Матрица охватывает все три формулы и оба пола: точные итоги из PRD, порядок ничьих
и отсутствующих строк, отсутствие лидеров, конечный ноль и отрицательные итоги,
малый/большой собственный вес, рост у полюсов и неконечный расчёт.
Точные ожидаемые итоги задаются литералами, а не пересчитываются тестом по формуле.
Точность коэффициентов подтверждают независимые эталоны T001–T003.

Проверка типов — `npm run typecheck`. Полный прогон чистого снимка — по
[E006-T001](../../e006-delivery-foundation/checks.md), с общим пользовательским кэшем
Chromium без повторного скачивания установленной версии. Итоговый review
сравнивает отдельную задачу с базой `0ccee14` по соглашениям и требованиям.
Покрытие приёмки эпика: позиции 2–8, итоговая сверка позиции 1.

## Результат и продолжение

Общая матрица подтверждает поведение существующего ядра; дефектов, требующих
изменения расчётного кода, не выявлено. Добавлены приёмочные регрессии и
[передача E008](../engine-handoff.md) с контрактом, точными входными примерами,
правилами представления и объяснением математических краёв формул.
E008 получил ссылку на этот вход; его интерфейс не реализован и не принят.

Полный прогон чистого снимка `6787dfebe902274ce1de3a0e17086d5c7abbe518`,
дерево `fa592997892b92b510b57d709b16c013fbc58de4`, завершился успешно:
установка по lockfile, Chromium из общего пользовательского кэша без скачивания,
синтетическая PostgreSQL, Prisma, форматирование, типы, сборка, 104/104 теста
без пропусков и очистка ресурсов. Итоговый независимый review относительно
`0ccee14`: Standards — 0 замечаний, Spec — 0 замечаний. Относительные ссылки
изменённых документов проверены. После проверенного снимка изменены только
результаты и статусы в документации. Расчётное ядро E007 принято;
продолжение S03 — интерфейс E008 по отдельной задаче.
