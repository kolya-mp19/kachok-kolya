# E005-T003. Сохранять неподтверждённый ввод на технической границе

## Что сделать

**Что даёт:** будущие формы используют согласованный механизм, в котором ошибка отправки не стирает введённое.

Согласованные решения S01 перенесены в [PRD](../prd.md), разделы 3, 8 и технические
решения E001. Разрешена реализация всего приложения локально, включая хранение
и необходимые зависимости. Внешние интеграции, удалённая инфраструктура и выпуск
отложены; E003/S01 не завершены и локальную реализацию не блокируют.


**Заблокирована:** [E005-T002](t002-owned-operation.md); общие мобильные состояния [E004-T003](../../e004-project-foundation/tasks/t003-loading-and-errors.md).

## Критерии готовности

- [x] Технический проход различает введённое, отправленное и подтверждённое; контролируемый неуспех сохраняет ввод.
- [x] Поддержаны согласованные S01 правила повторной отправки, без оффлайн-синхронизации и хранения сессии калькулятора.
- [x] Инструкция объясняет подключение границы; реальный ввод плана и факта остаётся приёмкой S06–S07.

## Проверка

Проверить публичную границу черновика/команды: зашифрованная запись IndexedDB завершается до отправки; ошибка сохраняет ввод; повтор использует прежний envelope; поздний ответ не удаляет новую редакцию; другой владелец не читает черновик; старое поколение восстановления отклоняется до квитанции. Проверить атомарную квитанцию и исторический результат через техническую операцию без сущностей будущих фич. Реальные формы остаются S06–S07. Использовать TDD на согласованных владельцем границах; регулярно запускать typecheck и целевые тесты, в конце полный набор тестов и независимые ревью стандартов и требований. Покрытие приёмки эпика: позиции 1, 7–9; итоговая сверка 2–6. «Позиция N» — N-й чекбокс основного раздела приёмки PRD; исходные критерии не имеют A-идентификаторов.

## Результат и продолжение

Реализованы [браузерная граница](../../../../../apps/web/src/diary/pending-input.ts),
[зашифрованное хранение](../../../../../apps/web/src/diary/encrypted-drafts.ts) и
[серверная граница квитанций/ключей](../../../../../apps/api/src/operations/operation-store.ts).
Постоянная схема содержит только технические ключи и квитанции. Редакция и изменение
прикладного корня передаются обработчиком внутри транзакции; продуктовых сущностей нет.
Подключение описано в [инструкции](../../../../../README.md#подключение-сохранности-ввода).

Границы TDD согласованы владельцем: публичные операции редактора, IndexedDB/WebCrypto
и серверный протокол с реальной отдельной PostgreSQL. Целевой серверный набор — 11/11;
браузерный — 19/19, включая обычное закрытие вкладки, ошибку квоты, ciphertext,
изменение аккаунта на технической границе, AAD, CAS, поздний ответ, прежнее поколение
и явную сверку. Проверки типов запускались регулярно. npm run build и полный npm test
успешны: 47/47, без пропусков, с PostgreSQL 18.6 и Chromium через установленный Chrome.
Проверены атомарный откат технической записи/квитанции, конкурентный повтор одного UUID,
ограничение трёх попыток и повторная проверка доступа после блокировки владельца.

Независимые ревью завершены: Standards — одно первоначальное замечание, Spec — три.
Исправлены гонка блокировки/повторного входа, преждевременный статус сохранности и
повтор после несовпавшего подтверждения; публичные регрессии прошли red → green.
Повторные независимые ревью подтвердили 0 открытых замечаний по каждой оси.
После исправлений сборка и полный набор повторены успешно. Следующее действие —
итоговая приёмка PRD оркестратором из чистой копии отслеживаемых файлов.
Реальные аккаунты/сессии и HTTP выдача ключа — S04; реальные формы плана/факта — S06–S07;
полный restore и отзыв восстановленных способов доступа — E029. Safari iOS/Chrome Android
на физических устройствах не проверены. Блокер внешних доступов E003 сохраняется,
E003/S01 не завершены; внешние интеграции, удалённая инфраструктура и выпуск не выполнялись.
