# E005-T001. Подготавливать и безопасно обновлять локальное хранилище

## Что сделать

**Что даёт:** разработчик документированной командой создаёт и обновляет хранилище с сохранением данных.

Согласованные решения S01 перенесены в [PRD](../prd.md), разделы 3, 8 и технические
решения E001. Разрешена реализация всего приложения локально, включая хранение
и необходимые зависимости. Внешние интеграции, удалённая инфраструктура и выпуск
отложены; E003/S01 не завершены и локальную реализацию не блокируют.


**Входы:** E004 принят, E001/E002 завершены; применяется локальная область раздела 3 PRD.

## Критерии готовности

- [x] Подключение и миграции следуют решениям S01; чистая схема готовится без ручных изменений.
- [x] Повторное применение безопасно, версия сохраняется после перезапуска, обновление сохраняет временные проверочные данные.
- [x] Ошибки подключения и миграции различимы без секретов и содержимого записей; инструкция описывает действия после неуспеха.
- [x] Не создаются модели всех будущих фич, калькулятор не подключается к хранилищу.

## Проверка

Проверить публичные команды подготовки, применения и статуса Prisma Migrate на отдельной локальной PostgreSQL: чистую схему, безопасный повтор, версию после перезапуска, обновление прежней синтетической схемы с сохранением записи. Проверить недоступное подключение и ошибочную миграцию: разные безопасные коды без URL, SQL-параметров и содержимого. Проверочные данные не становятся продуктовой моделью. Использовать TDD на согласованных владельцем границах; регулярно запускать typecheck и целевые тесты, в конце полный набор тестов и независимые ревью стандартов и требований. Покрытие приёмки эпика: позиции 1–5, 8–9. «Позиция N» — N-й чекбокс основного раздела приёмки PRD; исходные критерии не имеют A-идентификаторов.

## Результат и продолжение

Реализованы PostgreSQL 18.6 в локальном Compose с постоянным томом, Prisma ORM/Migrate 7.10.1 и команды db:generate/db:migrate/db:status/db:check. Начальная миграция создаёт только историю схемы Prisma, без продуктовых таблиц. Сырой вывод ORM и SQL-ошибки PostgreSQL не выводятся в диагностику. Инструкция подключения и исправления неуспешного обновления находится в [корневом README](../../../../../README.md).

Проверены npm run typecheck, npm run build и полный npm test: 11 из 11 проверок, без пропусков, с реальной PostgreSQL и Chromium через установленный Chrome. Целевой набор хранения: 4 из 4. Проверка журналов сначала выявила утечку текста SQL-ошибки и после исправления проходит. Отдельно выполнены db:migrate/db:status, перезапуск контейнера и повторный db:status: версия 202611110001_storage_foundation сохранилась. Обновление прежней синтетической схемы сохранило строку; неуспешная транзакционная миграция её не изменила. Калькулятор и оболочка продолжают запускаться без БД.

Независимые ревью стандартов и требований завершены; замечания об идентификаторе миграции, версиях в PRD и параметре schema исправлены. Поведенческие исправления проверены red → green, затем повторены сборка и полный набор тестов. Следующее действие — E005-T002 после коммита T001. Реальные личные операции, формы, внешние доступы и восстановление полной версии здесь не проверяются; E003/S01 не завершены.
