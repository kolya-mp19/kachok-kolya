# E005-T002. Подключать личную операцию с подтверждённым владельцем

## Что сделать

**Что даёт:** следующий эпик получает проверяемую техническую границу личной операции без доверия идентификатору из формы.

Согласованные решения S01 перенесены в [PRD](../prd.md), разделы 3, 8 и технические
решения E001. Разрешена реализация всего приложения локально, включая хранение
и необходимые зависимости. Внешние интеграции, удалённая инфраструктура и выпуск
отложены; E003/S01 не завершены и локальную реализацию не блокируют.


**Заблокирована:** [E005-T001](t001-storage-and-migrations.md).

## Критерии готовности

- [x] Техническая проверка показывает передачу владельца из подтверждённого контекста и отсутствие полномочий у одного лишь клиентского идентификатора.
- [x] Граница соответствует проекту доступа S01; постоянные продуктовые сущности и временный интерфейс не создаются ради проверки.
- [x] Калькулятор от механизма не зависит; полная проверка двух реальных аккаунтов явно остаётся в S04.

## Проверка

Согласованная граница TDD — публичный серверный запуск личной операции. Адаптер
доступа подключается только серверной сборкой приложения и проверяет актуальный
доступ при каждом запуске; он не принимается из запроса. Техническая проверка
использует синтетический адаптер этой границы без HTTP-маршрута входа. Операция
получает неизменяемый контекст владельца только после проверки. Идентификатор формы
служит ожидаемым владельцем для сверки и не подтверждает доступ.

Проверить публичную серверную границу личной операции: подтверждённый контекст передаёт владельца, один клиентский ID не авторизует, несовпадающий владелец отклоняется. Использовать технические обработчики без постоянной продуктовой сущности, HTTP-заглушки входа и временного UI. Проверка двух реальных аккаунтов остаётся S04. Использовать TDD на согласованных владельцем границах; регулярно запускать typecheck и целевые тесты, в конце полный набор тестов и независимые ревью стандартов и требований. Покрытие приёмки эпика: позиции 1, 6, 9. «Позиция N» — N-й чекбокс основного раздела приёмки PRD; исходные критерии не имеют A-идентификаторов.

## Результат и продолжение

Реализована [серверная граница личной операции](../../../../../apps/api/src/access/owned-operation.ts):
адаптер актуального доступа подключается только серверной сборкой приложения.
Операция получает неизменяемого владельца после проверки доступа и сверки ожидаемого
идентификатора. Недоверенный JSON, отсутствие владельца и несовпадение не запускают
изменение. Проверка повторяется при каждом запуске; после отзыва прежний доступ
не используется. Таблицы, продуктовый интерфейс и HTTP-маршруты входа не добавлены.
Подключение описано в [инструкции](../../../../../README.md).

Проверены npm run typecheck (регулярно), целевой набор owned-operation — 6 из 6,
npm run build и полный npm test — 17 из 17 без пропусков, с локальной PostgreSQL
и Chrome/Chromium. Первый полный запуск в песочнице выявил ограничение системного
вызова дочернего процесса Prisma; тот же набор вне песочницы прошёл полностью.
Отказы по недоверенному JSON, чужому/отсутствующему владельцу и запрет изменения
контекста пройдены red → green. Отказные проверки также подтверждают отсутствие
изменения синтетического значения. Браузерный проход подтверждает отсутствие API
у калькулятора; новых клиентских зависимостей не добавлено.

Независимые ревью стандартов и требований завершены: открытых замечаний нет.
Следующее действие — отдельная реализация T003 после коммита T002. Реальные сессии, проверки вложенных личных объектов
и два реальных аккаунта остаются в S04; эта техническая основа их не заменяет.
E003/S01 не завершены, внешние доступы не проверялись.
