# E005-T002. Подключать личную операцию с подтверждённым владельцем

## Что сделать

**Что даёт:** следующий эпик получает проверяемую техническую границу личной операции без доверия идентификатору из формы.

Согласованные решения S01 перенесены в [PRD](../prd.md), разделы 3, 8 и технические
решения E001. Владелец разрешил локальный E005, включая хранение и зависимости,
до завершения E003. Внешние интеграции, удалённая инфраструктура и выпуск не разрешены;
блокер внешних доступов E003 сохраняется, E003/S01 не завершены.


**Заблокирована:** [E005-T001](t001-storage-and-migrations.md).

## Критерии готовности

- [ ] Техническая проверка показывает передачу владельца из подтверждённого контекста и отсутствие полномочий у одного лишь клиентского идентификатора.
- [ ] Граница соответствует проекту доступа S01; постоянные продуктовые сущности и временный интерфейс не создаются ради проверки.
- [ ] Калькулятор от механизма не зависит; полная проверка двух реальных аккаунтов явно остаётся в S04.

## Проверка

Проверить публичную серверную границу личной операции: подтверждённый контекст передаёт владельца, один клиентский ID не авторизует, несовпадающий владелец отклоняется. Использовать технические обработчики без постоянной продуктовой сущности, HTTP-заглушки входа и временного UI. Проверка двух реальных аккаунтов остаётся S04. Использовать TDD на согласованных владельцем границах; регулярно запускать typecheck и целевые тесты, в конце полный набор тестов и независимые ревью стандартов и требований. Покрытие приёмки эпика: позиции 1, 6, 9. «Позиция N» — N-й чекбокс основного раздела приёмки PRD; исходные критерии не имеют A-идентификаторов.

## Результат и продолжение

Реализация не начата. После получения входных результатов уточнить технические проверки по согласованному PRD; при выполнении зафиксировать проверенный результат и оставшиеся действия. Состояние задачи ведётся только в реестре карточки эпика; перед остановкой там обновляются текущая точка и следующее действие.
