# Эпики реализации

Уровень 2 [общего плана](../README.md): каждый эпик объединяет законченный результат,
его PRD и задачи. Все шаги S01–S11 детализированы; для E001–E030 созданы
124 задачи уровня 3 с согласованными границами и зависимостями.
Подготовленный PRD не означает выполненный эпик или согласованный технологический стек.

## Текущая точка

- **Следующий эпик:** E003 — подтверждение внешних доступов и приёмка подготовленного проекта.
- **Следующее действие:** подтвердить внешние входы [T002 E003](./e003-release-design/design/environments-and-access.md), затем завершить приёмку T004/T005; [передача E001](./e001-technical-design/design/design-handoff.md) и [мобильные результаты E002](./e002-mobile-experience/design/design-handoff.md) уже использованы.
- **Условие начала создания проекта:** E001/E002 завершены, стек записан в ADR; завершение E003
  и остальные входные условия S01 до E004 сохраняются.
- [PLAN-Q1](../../requirements/week-planning/open-questions.md) закрывается до сравнения ввода с историей E016;
  [PROGRESS-Q1](../../requirements/progress-analytics/open-questions.md) — до совпадающих дат собственного веса E025/E027.
  Техническая передача эти продуктовые вопросы не закрывает.

## Переход к задачам

Перед разбиением эпика на задачи сверяются его PRD, актуальные требования и результаты
зависимостей. Не принятые ещё решения S01 остаются входными условиями будущих эпиков;
их нельзя считать согласованными только потому, что PRD уже написан.

Карточка эпика содержит реестр созданных задач с идентификаторами вида `E001-T001`,
статусами, чекбоксами и ссылками. Файлы задач размещаются в `tasks/` внутри эпика.
Реестры и отдельные файлы задач созданы для всех эпиков: восемь задач
[E001](./e001-technical-design/README.md) и 116 задач E002–E030.
Статус задачи ведётся только в карточке её эпика. Подготовка задач не означает
выполнения эпиков или снятия блокеров. Перед реализацией следующих шагов необходимо
перенести согласованные результаты S01 в зависимые PRD и уточнить технологические
проверки задач; до этого технологически нейтральные задачи остаются условными.
При смене активной задачи обновляется текущая точка карточки.

Если при детализации обнаружится продуктовый вопрос, он оформляется по
[правилам документации](../../README.md) в бизнес-спеке. Техническое решение, которое
ещё нужно принять при выполнении S01, является содержанием проектной работы;
выбранные решения записываются в PRD и, когда применимо, ADR после согласования.
