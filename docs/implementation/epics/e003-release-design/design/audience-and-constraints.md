# Аудитория и эксплуатационные ограничения

Проектный результат [E003-T001](../tasks/t001-audience-and-constraints.md).
Основания — действующие требования, подтверждённые ограничения E001 и прямое
уточнение владельца: первая аудитория — он сам и ещё несколько человек, нагрузка
минимальна; бюджет не рассматривать и не учитывать. Процедуры выбраны в рамках
делегированного проектирования; владение внешними аккаунтами проверяется при подключении.

## Первый доступ

| Условие | Решение и основание | Проверка перед выпуском |
|---|---|---|
| Аудитория дневника | Владелец и ещё несколько знакомых; прямое уточнение владельца согласуется с [бэклогом](../../../../backlog.md), «Удаление аккаунта» | Владелец сверяет фактический круг получателей доступа с этой границей |
| Начало знакомства | Анонимный калькулятор; дневник открывается явным действием, затем регистрацией или входом по [auth](../../../../requirements/auth/index.md) | Открытие калькулятора не требует аккаунта и не обращается к API дневника |
| Способы входа | Яндекс, ВКонтакте и запасной вход по почте; восстановление через подтверждённую почту | Каждый способ проходит собственную приёмку, недоступность одного не выдаётся за готовность всех |
| Предоставление доступа | Владелец передаёт ссылку знакомым после выполнения условий выпуска | Передача ссылки не означает общей регистрации для незнакомой аудитории |
| Решение о выпуске | Принимает владелец продукта по результатам E028–E030 | Есть решение по конкретной сборке и аудитории; агентская проверка документов не заменяет его |

Новая система приглашений, административные роли и список разрешённых аккаунтов
не вводятся. Передача ссылки знакомым сама по себе не ограничивает техническую
возможность регистрации. Поэтому владелец перед каждым расширением доступа
проверяет аудиторию; наличие общедоступной ссылки нельзя считать доказательством
сохранения принятой границы.

Триггер удаления аккаунта сейчас не применяется к согласованному кругу знакомых.
До доступа первого незнакомого атлета владелец возвращает удаление аккаунта и данных
в бизнес-требования, определяет реализацию и приёмку; E030 проверяет их выполнение.
Поток удаления не проектируется внутри E003. Анонимное использование калькулятора
не создаёт аккаунт дневника и само по себе не запускает этот триггер.

## Размещение и сопровождение

Из [ограничений E001](../../e001-technical-design/design/constraints.md) приняты один
имеющийся сервер, Docker Compose, TypeScript, React SPA, NestJS, Prisma и PostgreSQL.
Владелец подтвердил готовность сопровождать Node.js/PostgreSQL по воспроизводимой
инструкции. Инструкция должна позволять чистый запуск, настройку, миграции,
диагностику и продолжение сопровождения без неописанного знания.

Бюджет исключён из этой проектной работы прямым указанием владельца и не является
блокером приёмки. Услуги здесь не заказываются. Наличие домена, внешних аккаунтов и
возможность подключения проверяются по [проекту окружений E003-T002](../tasks/t002-environments-and-access.md).

Для минимальной нагрузки и нескольких атлетов выбрано сопровождение
владельцем по мере возможности, без круглосуточного дежурства и обещания срока
реакции. Часы доступности не предполагаются. Это проектное решение опирается на
подтверждённую готовность E001 сопровождать систему по инструкции; отдельный график
для выбранных процедур не требуется. Ответственный за выпуск — владелец; его
решение о конкретной сборке принимается в E030 и не блокирует подготовку проекта.

## Сохранность и входы соседних задач

| Получатель | Ограничение |
|---|---|
| E001, E004–E006 | Один сервер не означает общие данные окружений: локальные, тестовые и рабочие данные, конфигурация и секреты разделяются |
| E001, E009–E011 | Секреты поставщиков вне git; тестовая почта не отправляется настоящим атлетам; провайдеры не заменяют запасной вход и восстановление по почте |
| E003-T003 | Матрица Safari/iOS и Chrome/Android из [E002](../../e002-mobile-experience/design/constraints-and-validation.md); ввод с клавиатурой, потеря связи, сессии и исправления истории обязательны |
| E003-T004, E029 | Возврат версии отличается от восстановления данных; необходимо проверять дневник после восстановления, а не только доступность сервера |
| E003-T005, E030 | Выпуск требует конкретной аудитории, завершённых проверок и проверки триггера удаления перед расширением доступа |

Ожидание сохранности ввода следует П4 и [протоколу E001](../../e001-technical-design/design/input-preservation.md):
потеря ответа не создаёт дубль, подтверждение старой редакции не удаляет новую,
чужой аккаунт не получает прежний черновик. Это не гарантия сохранности при потере
сервера. Состав и параметры копий, допустимая потеря данных и срок восстановления
проектируются отдельно в T004 и подтверждаются до выпуска; наличие механизма
и успешный прогон проверяются в E029. Исключение копий из работы E001 не снимает
эти условия E003/E029.

## Проверка результата

Аудитория подтверждена владельцем; способы входа прослеживаются до существующих
требований; публичный доступ не добавлен. Технические ограничения совместимы с
принятым Compose-проектом и передаются в T002–T005. Бюджет исключён прямым
указанием, сопровождение организовано без выдуманного графика и сроков реакции.
Проверки приложения, типов и тестов неприменимы к этому документальному результату.
