# E010-T004. Явно подключать новый провайдер к существующему дневнику

## Что сделать

**Что даёт:** атлет с совпавшей либо другой почтой нового провайдера подтверждает оба способа и продолжает вести один дневник.

До исполнения согласованные результаты S01 должны быть перенесены в зависимый PRD; границы, размер задачи и проверки уточняются по выбранным технологиям. Согласование разбивки не означает выбора стека или разрешения создавать проект. Общий блокер — результаты S02 (завершённые E004–E006), подготовленные на основе согласованного S01. Нужен готовый E009 и согласованный проект доступа. До подключения проверяются актуальные официальные инструкции и доступность интеграций для выбранного приложения. Каждый срез включает защищённые операции, хранение, русские мобильные формы и проверку результата.

**Заблокирована:** [E010-T001](t001-yandex-login.md), [E010-T002](t002-vk-login.md); подтверждённое владение существующим аккаунтом через E009 или ранее подключённый способ.

## Критерии готовности

- [ ] Совпадение почты само по себе не подключает способ; владение обоими подтверждается в ходе данного действия.
- [ ] После подключения через каждый способ открывается один идентификатор дневника, адрес восстановления и записи сохраняются даже при другой почте провайдера.
- [ ] Внешнюю идентичность другого дневника нельзя перенести, дневники не объединяются; отмена и неуспех не меняют связи.
- [ ] Повтор и конкурентное подключение не обходят принадлежность способа одному дневнику.

## Проверка

Пройти описанный сценарий и проверить каждый критерий готовности на наблюдаемом результате. Покрытие приёмки эпика: A4–A6, A7 в части исключительных мобильных потоков.

## Результат и продолжение

Реализация не начата. После получения входных результатов уточнить технические проверки по согласованному PRD; при выполнении зафиксировать проверенный результат и оставшиеся действия. Состояние задачи ведётся только в реестре карточки эпика; перед остановкой там обновляются текущая точка и следующее действие.
