# E006-T002. Развёртывать проверенную сборку в изолированном тестовом окружении

## Что сделать

**Что даёт:** разработчик повторяемо получает доступную тестовую версию и знает, какая сборка работает.

До исполнения согласованные результаты S01 должны быть перенесены в зависимый PRD; границы, размер задачи и проверки уточняются по выбранным технологиям. Согласование разбивки не означает выбора стека или разрешения создавать проект. Общий блокер — завершённые E001–E003, согласованный с владельцем стек и соответствующие решения в PRD.

**Заблокирована:** [E006-T001](t001-automated-checks.md); [E004-T002](../../e004-project-foundation/tasks/t002-mobile-navigation.md)/[E004-T003](../../e004-project-foundation/tasks/t003-loading-and-errors.md); [E005-T001](../../e005-storage-foundation/tasks/t001-storage-and-migrations.md).

## Критерии готовности

- [ ] Конфигурация и секреты отделены, личные рабочие данные не используются; работающая сборка прослеживается до git.
- [ ] Применяются миграции и проверяются оболочка, прямые ссылки и подключение хранилища; повторное развёртывание сохраняет проверочные данные.
- [ ] Инструкция ссылается на команды E004/E005 и позволяет повторить процесс без неописанных настроек машины автора.

## Проверка

Пройти описанный сценарий и проверить каждый критерий готовности на наблюдаемом результате. Покрытие приёмки эпика: позиции 1, 5–6, 9–10. «Позиция N» — N-й чекбокс основного раздела приёмки PRD; исходные критерии не имеют A-идентификаторов.

## Результат и продолжение

Реализация не начата. После получения входных результатов уточнить технические проверки по согласованному PRD; при выполнении зафиксировать проверенный результат и оставшиеся действия. Состояние задачи ведётся только в реестре карточки эпика; перед остановкой там обновляются текущая точка и следующее действие.
