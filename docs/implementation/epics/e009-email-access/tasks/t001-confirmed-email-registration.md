# E009-T001. Создавать дневник после подтверждения новой почты

## Что сделать

**Что даёт:** атлет с телефона регистрируется по почте и получает ровно один пустой личный дневник после подтверждения адреса.

Поднять Mailpit в Docker, подключить приложение по SMTP и пройти регистрацию
от запроса письма до подтверждения по ссылке из веб-интерфейса Mailpit.
Отправка используется последующим восстановлением пароля; доставка во внешние ящики не входит.

Для проверки с телефона в E009-T001 настраивается защищённый локальный доступ: HTTPS с локальным доверенным сертификатом к машине разработки, единый origin приложения и API. Публичный домен, внешний DNS/TLS-провайдер и удалённый сервер не нужны. HTTP по LAN не подходит для Web Crypto; loopback-исключение localhost телефона не распространяется на машину разработки. На локальном HTTPS используется защищённая cookie `__Host-session` с Secure/HttpOnly/SameSite=Lax/Path=/ без Domain; разрешённый Origin и адрес ссылок писем задаются конфигурацией, а не заголовком Host. SMTP и веб-интерфейс Mailpit остаются доступны только на loopback машины разработки: письмо читается там, а ссылка открывается на телефоне через настроенный локальный HTTPS origin. Локальные ключи CA и сертификатов не включаются в git. Доверие сертификату, API, cookie, IndexedDB/Web Crypto и ссылки писем проверяются до приёмки мобильного сценария; последующие эпики используют эту инструкцию.

Вход — локальные результаты S02 и принятые решения E001/E002. Внешние доступы E003 и развёртывание не блокируют исполнение. Каждый срез включает защищённые операции, хранение, русские мобильные формы и проверку результата. Пароли защищаются Argon2id, токены писем хранятся хешами с назначением и однократным потреблением; сроки действия, повторная отправка и ограничения попыток проверяются локально.

**Заблокирована:** локальные результаты S02 и принятый проект аутентификации E001; SMTP Mailpit настраивается в этой задаче без внешних доступов.

## Критерии готовности

- [ ] Защищённый локальный HTTPS origin доступен с телефона с доверенным локальным сертификатом; API, защищённая cookie сессии, проверка Origin и IndexedDB/Web Crypto работают. Настройка воспроизводима по инструкции без публичного домена, внешних DNS/TLS и удалённого сервера; ключи не попадают в git.

- [ ] Mailpit включён в локальный Docker Compose: SMTP и веб-интерфейс доступны только локально; инструкция задаёт SMTP-адрес для приложения и адрес веб-интерфейса. Внешние SMTP-сервисы не подключаются.
- [ ] Проверочное письмо видно в веб-интерфейсе Mailpit; ссылка ведёт на настроенный origin локального приложения; на телефоне используется защищённый локальный HTTPS origin, токен имеет назначение, ограниченный срок и однократное использование; результат отправки отличается от подтверждения владения адресом. Недоступность канала и отказ отправки дают проверяемый неуспешный результат, сохраняя возможность разрешённого повтора по S01.
- [ ] Имя, почта и пароль вводятся в русских формах; запрос и отправка письма ещё не создают дневник.
- [ ] Подтверждение создаёт атлета и дневник согласованно; повтор и одновременное завершение не создают дубликаты.
- [ ] Отмена, непригодное подтверждение и сбой доставки не создают аккаунт и не дают доступ; секреты не попадают в диагностику.

## Проверка

Пройти регистрацию с локальными тестовыми адресами через SMTP и веб-интерфейс Mailpit,
проверить приём письма, подтверждение, отказ отправки и недоступность канала. Письмо читается на машине разработки через loopback UI Mailpit; ссылка открывается на телефоне в настроенном HTTPS origin. Проверить доверие сертификату, cookie, API и доступность Web Crypto/IndexedDB. Сверить,
что запрос и отправка не создают дневник, а повтор подтверждения не создаёт дубликат.
Покрытие приёмки эпика: A1, A5–A6; подключение доставки по разделу «Операции» PRD.

## Результат и продолжение

Реализация не начата. После получения входных результатов уточнить технические проверки по согласованному PRD; при выполнении зафиксировать проверенный результат и оставшиеся действия. Состояние задачи ведётся только в реестре карточки эпика; перед остановкой там обновляются текущая точка и следующее действие.
