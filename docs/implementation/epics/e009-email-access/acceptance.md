# Проверки локального почтового доступа

## Интерфейс T001

Используется согласованный язык E002: фон `#f6f7f9`, поверхность `#ffffff`,
текст `#17212b`, пояснения `#556270`, действие `#2457a7`, граница `#c8d0da`.
Системный sans-serif сохраняет принятые метрики и знакомое поведение менеджера паролей;
заголовки 24/32 и 20/28, основной текст 16/24. Выравнивание по левому краю.

```text
Дневник
План тренировок и записи о выполнении

Регистрация по почте
Имя
[                         ]
Почта
[                         ]
Пароль
[                         ]
[ Отправить письмо        ]
```

Одна форма на всю полезную ширину экрана; ожидание письма и подтверждение заменяют
форму последовательно. Успех показывает пустой дневник с будущим шагом создания
цикла, без кнопки неработающей операции. Проверка плана по brief сохранила токены
и навигацию E002: новая декоративная карточка и собственный акцент здесь не нужны.
Отличительная часть — ясное разделение отправленного письма и подтверждённого
дневника. Ошибка сохраняется рядом с действием, пароль при отказе не стирается.

## Покрытие

`npm run build`, `npm run format:check` и полный `npm test` прошли: 144 теста,
без отказов и пропусков. Отдельный файл регистрации содержит 12 успешных проверок,
файл входа по паролю — 8, восстановления — 13; все проверки без пропусков.
Итоговый code-review по Standards и Spec не оставил нерешённых замечаний.
Чистый снимок программной реализации T003 прошёл `npm run check`: установка
по lockfile, браузер, отдельные PostgreSQL/Mailpit на случайных loopback-портах,
Prisma, форматирование, типы, сборка, 144/144 теста и очистка окружения.
Дополнительный локальный smoke проверил HTTPS Vite с исходным API через tsx,
SMTP, `__Host-session`, Web Crypto AES-GCM и запись IndexedDB. Для него использован
временный синтетический сертификат и разрешение его ошибки в тестовом Chromium;
доверие CA и физические браузеры этим не проверены.

## Интерфейс и проверки T002

Сохранены цвета, типографика и левое выравнивание E002 из проекта T001.
Стартовый экран дневника показывает вход, а создание нового дневника — отдельное
явное действие. Это сокращает путь возвращающегося атлета; декоративные карточки
и новый визуальный акцент после сверки с brief не добавлялись.

```text
Вход по почте
Почта
[                         ]
Пароль
[                         ]
[ Войти                  ]
[ Создать дневник        ]
```

Регистрация содержит действие «Войти в прежний дневник». При занятом адресе
показывается понятное сообщение и остаётся этот действующий путь. Формы принимают
менеджеры паролей, сохраняют ввод при неуспехе и блокируют повторную отправку.
Снимок Chromium 320 px с текстом 200% просмотрен: горизонтальной прокрутки нет,
подписи и действия читаемы. Это не подтверждает настоящую клавиатуру iOS/Android.

Отдельный файл [проверок входа](../../../../tests/password-login.test.mjs) проверяет
правильный пароль с нормализацией адреса, прежние идентификаторы и сохранность записей,
ротацию сессии/CSRF, текущую редакцию доступа, одинаковый отказ неизвестному адресу,
неверному паролю и отсутствующему хешу, защиту Origin/CSRF, лимиты по IP и адресу.
Реальная гонка в PostgreSQL удерживает блокировку владельца, меняет пароль и редакцию
перед её снятием: старое доказательство не создаёт сессию. Браузерный сценарий проходит
от повторной регистрации к успешному входу и перезагрузке того же дневника.
Полный набор также проверяет переходы и ошибки мобильной оболочки с новым стартовым
экраном входа; HTTP-порты почтовых тестов не пересекаются с тестами калькулятора.

## Интерфейс и проверки T003

Восстановление сохраняет палитру, системный шрифт, метрики и левую мобильную колонку
E002. После сверки плана с brief убраны самостоятельные декоративные блоки:
главное содержание — возвращение к прежнему дневнику без изменения его записей.

```text
Вход по почте
[ Забыли пароль          ]
           ↓
Восстановление доступа
Почта [                  ]
[ Отправить письмо       ]
           ↓ ссылка из письма
Новый пароль
[                        ]
[ Установить пароль      ]
           ↓
Пароль установлен
[ Войти                  ]
```

Принятый запрос письма не выдаётся за доставку или подтверждение владения.
Одинаковый ответ для известной и неизвестной почты сохраняется при SMTP-отказе:
иначе отказ только существующему адресу раскрывал бы его регистрацию. Состояние
`deliveryFailedAt` и отсутствие `deliveredAt` дают проверяемый внутренний результат;
такой токен не пригоден. Повтор допустим; явная отмена хранится отдельно и запрещает
повтор отменённого запроса. Без почты или подключённого способа автоматическое
восстановление не обещается. После установки пароля требуется обычный вход.

[Проверки восстановления](../../../../tests/password-recovery.test.mjs) используют
настоящие PostgreSQL и Mailpit. Они сверяют прежний diaryId и проверочные записи,
отказ прежним сессиям/паролю/остальным ссылкам, срок 30 минут и назначение,
отмену, повтор, Origin/CSRF, адресные лимиты, отсутствующий после восстановления
копии БД хеш, конкурентные разные/одинаковые ссылки и гонку со входом.
Искусственный сбой отзыва сессий проверяет откат пароля, редакции и потребления токена.
SMTP reject и недоступный канал не меняют доступ; неизвестная почта не получает письмо.
В Chromium 320 px с текстом 200% проверены отмена, удаление фрагмента URL,
сохранение нового пароля при отказе и обычный вход в прежний дневник после успеха.
Снимок интерфейса просмотрен: поля и действия читаемы, горизонтальной прокрутки нет.
Регрессии дополнительно задерживают ответ старой ссылки при открытии новой в той же
вкладке и проверяют, что поздний ответ не заменяет новый экран и не переносит пароль.
Истёкшее доказательство формы отклоняется до изменения данных; следующая явная попытка
обновляет его без автоматического повтора POST и без стирания введённого пароля.

## Оставшаяся приёмка T001

Пройти [протокол на телефоне](../../../local-email-access.md#приёмка-на-устройстве)
в настоящих Safari iOS и Chrome Android. До этой проверки T001 остаётся «В работе»;
локальная реализация регистрации может использоваться следующими задачами.
Внешние провайдеры, SMTP и развёртывание остаются отложенными.
