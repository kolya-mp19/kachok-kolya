# Первый ручной план и факт

Проектный результат [E001-T002](../tasks/t002-manual-plan-and-fact.md).
Документ определяет логическую модель и границы операций; таблицы и типы хранения
будут реализованы в последующих эпиках. Ручное планирование и запись факта работают
без МПВ и без предписания цикла.

## Границы модулей

| Модуль | Владеет | Публичные операции |
|---|---|---|
| Доступ | Аккаунт, способы входа, сессии | Получить подтверждённого владельца операции; остальные операции проектируются в [T006](../tasks/t006-access-and-trust.md) |
| Справочники дневника | Личные упражнения, связи с системными упражнениями, залы, текущие параметры упражнения у атлета | Найти/создать упражнение, получить/изменить настройки, выбрать зал, явно изменить связь |
| Циклы | Цикл, недели, назначение, роли, исходные МПВ и согласованные цели | Создать цикл, получить положение в цикле, вычислить предписание; календарь и прерывание проектируются в [T003](../tasks/t003-calendar-and-interruption.md) |
| Планирование | Тренировки, упражнения и подходы плана, признак фиксации | Создать тренировку, изменить план, скопировать неделю, получить план для выполнения |
| Разминка | Общие комплексы, сохранённый для тренировки комплекс, отметка и результаты | Изменить общий комплекс, отметить/снять выполнение или пропуск, проверить доступ к новым подходам |
| Выполнение | Факт подхода, фактическая дата, RPE, замена и облегчённое выполнение, сохранённые условия выполнения | Записать/исправить/снять факт, записать замену, получить историю выполнения |
| Результаты дневника | Производные состояния и показатели, МПВ и динамика | Получить согласованные результаты; пересчёт источников проектируется в [T004](../tasks/t004-history-recalculation.md) |
| Калькулятор | Спортсмены, попытки, выбранная формула и рейтинг в памяти вкладки | Изменить спортсмена/попытки, выбрать формулу, рассчитать рейтинг |

Это границы ответственности внутри будущего монолита, а не отдельные сервисы.
Одна прикладная операция может согласованно изменить планирование, разминку и выполнение.
Клиент не вызывает внутренние записи модулей по отдельности, чтобы собрать первый факт.
Модуль результатов читает источники, но не изменяет введённый план ради показателя.

У калькулятора отдельная точка входа без загрузки профиля, проверки сессии и запросов
к API дневника. Он не читает собственный вес атлета, черновики или браузерное хранилище
дневника. После перезагрузки его состояние исчезает. Между калькулятором и дневником
нет общих доменных моделей и расчётов; общие только визуальные элементы без доступа к данным.

## Владение и идентификаторы

Аккаунт имеет устойчивый идентификатор атлета. Каждый личный корень данных содержит
идентификатор владельца; вложенные записи принадлежат тому же владельцу через родителя.
Сервер получает владельца из проверенной сессии, а не из присланного поля.
Для каждой операции проверяется вся цепочка: подход → упражнение в тренировке →
тренировка → неделя → цикл → атлет. Идентификатор сам по себе не даёт доступа.
Выбор личного упражнения, зала или комплекса другого владельца запрещён.
Системные упражнения и шаблоны цикла доступны для чтения как общие справочники.

У цикла, недели, тренировки, упражнения в тренировке, планового подхода и стороны замены
свои устойчивые непрозрачные идентификаторы. Название и дата тренировку не идентифицируют.
Копирование создаёт новые идентификаторы всех вложенных записей; ссылки на выбранные
упражнения сохраняет. У факта ключом служит идентификатор планового подхода:
повторное изменение факта меняет ту же запись, а не добавляет ещё один подход.
Распознавание повторной команды после потери ответа дополнительно проектируется в [T007](../tasks/t007-input-preservation.md).

Изменяемый корень имеет номер редакции. Команда передаёт ожидаемую редакцию;
проверка и изменение происходят согласованно. Конкурирующая правка не затирает
новый план: клиент получает конфликт и сохраняет свой ввод до разбора расхождения.

## Логическая модель

| Запись | Существенные данные | Что важно различать |
|---|---|---|
| Цикл и недели | Владелец, выбранный шаблон с сохранёнными ролями, даты недель, назначение, цели по упражнениям и их исходные условия | В первом развивающем цикле исходных МПВ и числовых целей нет; недели и ручной план существуют |
| Тренировка | Неделя, порядок в плане, имя, планируемая дата, зал, ссылка на комплекс, комментарий, редакция | Планируемая дата не заменяет фактическую; отдельного задаваемого статуса выполнения нет |
| Упражнение в тренировке | Исходно выбранное личное или системное упражнение, порядок, отдых между подходами | Связь с системным не заменяет исходный идентификатор источника |
| Плановый подход | Порядок, плановый вес, единица веса, повторения и роль | Повторения: точное число, включительный диапазон или «до отказа»; у отказного планового числа нет |
| Фиксация основной части | Момент и причина фиксации; состав, порядок, значения всех подходов и тип каждого упражнения | Тип «основное / вспомогательное» сохраняется для всей тренировки при её фиксации |
| Выполнение упражнения | Ссылка на исходную запись плана, RPE, облегчённое выполнение с причиной, состояние подбора веса при первом факте упражнения | Подбор относится к этому выполнению, а не ко всей тренировке и не к сегодняшней настройке |
| Факт подхода | Идентификатор планового подхода, фактический вес и повторения вместе, время записи | Нет факта отличается от указанного веса с нулём повторений |
| Фактическая дата тренировки | Календарная дата реального выполнения | При первом факте предлагается сегодняшняя дата; при поздней записи атлет задаёт действительную дату |
| Сохранённая разминка | Независимый признак фиксации, состав и цели комплекса, отметка выполнения/пропуска, причина пропуска и необязательные результаты | Пустой сохранённый комплекс тоже фиксируется и не создаёт требования разминки задним числом |
| Замена | Исходное упражнение в тренировке, заменяющее упражнение, его отдельно введённые план и факт | Исходные подходы и их факты не переносятся и не стираются |
| История настроек | Действия включения/снятия подбора с моментом действия и порядком | Нужна для определения состояния на фактическую дату поздней записи |
| Производные результаты | Исходы подходов, состояния тренировок, показатели соблюдения, МПВ и динамика | Пересчитываются из источников; не становятся новым планом |

Незавершённый ввод — отдельный клиентский черновик, а не факт. Он может содержать
исходный текст, частично набранное число, ошибочную дату и ещё не подтверждённый разбор.
Место его хранения и отправка определяются в T007. Сохранённая сервером копия плана
без весов допустима как редактируемая структура, но не пригодна для первой отметки.
Для сохранённого зафиксированного незавершённого плана после календарного события
обязательные значения не выдумываются; этот случай разбирается в T003.

Вес хранится точным десятичным значением в единице выбранного упражнения, без
пересчёта «кг на руку» в общий вес. `27,5` и `27.5` имеют одно числовое значение.
У факта либо заполнены вес и целое неотрицательное число повторений, либо факта нет.
Неполная пара не заменяет ранее сохранённый факт. Время записи назначает сервер;
оно не подменяет фактическую дату выполнения.

Предписание цикла вычисляется из сохранённых условий цикла, роли недели и доступного
МПВ. Оно не хранится как самостоятельный план и не записывает значения подходов.
Принять предложенный вес выбранных рабочих подходов и принять диапазон повторений —
разные явные действия. Если МПВ нет, предписание отсутствует и ручной ввод доступен.

## Нотация, роли и копирование

Разбор по мере ввода `20/30/40/50/60*6-8` даёт пять плановых подходов:

| Порядок | Вес, кг | Повторения | Роль |
|---|---|---|---|
| 1–4 | 20; 30; 40; 50 | 6–8 у каждого | Разминочный |
| 5 | 60 | 6–8 | Рабочий |

Сохраняются отдельные строки подходов, а не нотация. `60*8*3` разворачивается в три
подхода; `30+30*8` при «кг на руку» — один подход 30 кг на руку. Несовместимая
с единицей запись не подтверждается как корректная. Подозрительный, но допустимый
разбор показывается отдельно и требует подтверждения; неизвестные пороги сравнения
с прошлым выполнением остаются в существующем [PLAN-Q1](../../../../requirements/week-planning/open-questions.md).
Роли по правилу пика доступны для ручной правки до фиксации. При записи факта роль
не вычисляется заново из фактического веса: намерение уже сохранено.

Копирование заполненной прошедшей недели в будущую пустую неделю активного цикла
создаёт структуру без весов: даты сдвигаются по дням недели, имена, порядок, комментарии,
отдых, комплексы, роли и повторения сохраняются. Веса всех подходов требуют явного
ввода. История и предписание показываются как подсказки, не заменяя пропущенные значения.
Факт, отметки разминки, RPE и признаки выполнения не копируются. Текущая неделя
не является ни источником, ни приёмником этой операции; её заполняют вручную.

## Граница первой отметки

Команда записи первого факта принимает идентификатор подхода, ожидаемую редакцию,
целостную пару фактических значений и допустимую фактическую дату. Сервер в одной
согласованной операции:

1. Проверяет владельца, цикл, дату и редакцию; до начала цикла запись запрещена.
2. Проверяет разминку: пустой комплекс открывает основную часть; непустой требует
   отметки выполнения или пропуска с причиной. Неудачная проверка не стирает ввод.
3. Проверяет обязательные значения **всех** подходов тренировки. Если в копии отсутствуют
   веса, возвращает список недостающих значений без записи факта и без фиксации основной части.
4. Если основная часть ещё не зафиксирована, фиксирует весь состав, порядок, веса,
   повторения, роли и типы упражнений. Если разминка не фиксировалась, сохраняет её комплекс.
5. Для впервые начатого упражнения сохраняет подбор веса, действовавший на фактическую
   дату; уже начатое упражнение сохраняет прежнее условие. Подбор другого ещё не начатого
   упражнения определяется при его собственном первом факте.
6. Записывает пару фактических значений и дату тренировки, получает согласованные
   производные результаты и возвращает подтверждённую редакцию.

Либо применяются все изменения, либо ни одно. Нельзя подтвердить факт, оставив план
редактируемым, или зафиксировать план после неуспешной попытки записи. Календарные
причины фиксации рассматриваются отдельно в T003.

Отметка выполнения или пропуска разминки фиксирует только её состав и цели.
Она не закрывает редактирование основной части. Правка общего комплекса после этого
не меняет сохранённую разминку. Снятие отметки непустой разминки не удаляет подходы:
просмотр и исправление существующего факта доступны, запись новых подходов требует
снова отметить разминку либо пропуск. Снятие всех фактов основной части тоже не снимает
фиксацию её плана. Имя тренировки, комментарий и отдых можно менять по бизнес-спеке.

## Проверочный проход без МПВ

Все шаги выполняет один подтверждённый владелец; чужие идентификаторы отклоняются
до чтения или изменения личных записей.

| Действие | Вход | Изменение состояния | Что видит атлет |
|---|---|---|---|
| Создать первый цикл | Шаблон развивающего цикла, допустимый понедельник | Создаются цикл и недели; исходного МПВ нет | Роль недели, ручное планирование без предписания |
| Создать тренировку текущей недели | Имя «Грудь», дата внутри недели, первый зал | Создаются тренировка, личный зал и первый пустой комплекс «Обычная» | Предложение наполнить комплекс, основная часть доступна |
| Наполнить разминку | Одно разминочное упражнение и цель | Меняется общий ещё не сохранённый для тренировки комплекс | Для новых подходов нужна отметка разминки |
| Задать упражнение и план | Личное упражнение, единица «кг», `20/30/40/50/60*6-8` | Создаются структурные подходы; новое упражнение находится в подборе веса | Разбор с ролями; МПВ и числовая цель не требуются |
| Отметить разминку | «Выполнена» | Состав разминки фиксируется; основная часть остаётся редактируемой | Основная часть открыта; план ещё можно явно изменить |
| Дополнить основную часть | Ещё одно упражнение, полный план всех его подходов | Редактируется та же тренировка | Оба упражнения готовы к первой отметке |
| Отметить первый подход | Действие «Отметить 20 × 6», допустимая дата | Фиксируется план обоих упражнений; записывается факт 20 кг × 6; подбор сохраняется для первого упражнения | Подход отмечен, исходные планы всех подходов доступны |
| Указать провалённую попытку | 60 кг × 0 у рабочего подхода | Пара значений записана; роль остаётся рабочей | «Провалённая попытка» отличается от неотмеченных подходов |
| Снять все факты | Идентификаторы ранее отмеченных подходов | Факта нет; фиксация плана и сохранённые условия остаются | Подходы не отмечены; исходный план не открывается |
| Попробовать первую отметку в копии без весов | Структура с отсутствующим плановым весом хотя бы одного подхода | Факта нет, основная часть не фиксируется | Перечень недостающих значений; введённое не теряется |

Точность плана сравнивает только участвующие рабочие подходы; подбор сам по себе
не исключает их из точности. Разминка и разминочные подходы не создают МПВ.
Первый МПВ может появиться только по допустимой проходке завершённого развивающего
цикла. Первая ручная запись не создаёт его автоматически.

## Проверка критериев T002

| Критерий | Проверка проекта |
|---|---|
| Независимость калькулятора и публичные операции | Таблица модулей; открытие калькулятора без сессии не вызывает API и не читает хранилище дневника |
| Владение, идентификаторы, план, факт и условия | Логическая модель; чужой подход отклонён; неполная пара остаётся черновиком |
| Структура нотации, роли и копия | Пять строк примера; скопированный план без весов не допускает первую отметку |
| Фиксация всей тренировки и отдельная разминка | Отметка разминки допускает правку основной части; первый факт фиксирует оба упражнения |
| Тип, подбор и вычисляемое предписание | Тип сохраняется при фиксации; подбор — при первом факте упражнения; отсутствие МПВ не блокирует ручной путь |

Проверка выполняется проходом таблиц и сверкой с бизнес-спеками; исходного кода,
проверки типов и тестового набора приложения на этом этапе нет. Моменты календарной
фиксации и поздние изменения передаются в T003 и T004 соответственно.
