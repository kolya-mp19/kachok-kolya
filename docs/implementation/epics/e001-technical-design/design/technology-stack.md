# Выбранная техническая основа

Проектный результат [T005](../tasks/t005-technology-stack.md): TypeScript, React SPA/Vite,
NestJS, Prisma ORM, PostgreSQL, Ant Design и Tailwind CSS. Основание выбора и реальные
альтернативы — [ADR-0020](../../../../architecture/adr/ADR-0020-javascript-modular-monolith.md),
проверенные первичные источники — [исследование](./technology-research.md).

Выбор соответствует поручению владельца взять NestJS, если он подходит, и в этом случае
использовать Prisma; TypeScript и один сервер с Docker Compose подтверждены отдельно.
Предварительные варианты превращаются в решение после проверки доменных сценариев.
Создание проекта и установка зависимостей в эту задачу не входят.

## Ответственность технологий

| Часть | Выбор и ответственность | Граница |
|---|---|---|
| Интерфейс | React SPA, Vite, TypeScript | Отдельная клиентская точка калькулятора; маршруты дневника не загружаются ради расчёта |
| Готовые компоненты | Ant Design | Формы, кнопки, сообщения и фокус; мобильные сценарии подтверждаются E002, а не названием библиотеки |
| Стили | Tailwind CSS | Компоновка; слои `theme, base, antd, components, utilities`, тема компонентов через токены Ant |
| Сервер | NestJS/Node.js, модульный монолит | Валидация, владение, сессии, календарь и бизнес-операции; не перекладываются в SPA |
| Хранение | Одна PostgreSQL и Prisma ORM | Источники и производные результаты меняются атомарно; десятичные веса не проходят через двоичный `number` |
| Миграции | Prisma Migrate | Подготовка SQL в разработке, проверка на отдельной БД, применение готовых миграций при выпуске |
| Размещение | Один сервер, Docker Compose | HTTPS reverse proxy со статикой, API и внутренняя БД; постоянный том; один origin для SPA/API |

В S02 фиксируются поддерживаемые стабильные версии, совместимость Node.js и библиотек,
lockfile и команды сборки. Для хранения выбирается адаптер с явной изоляцией транзакций,
обработкой конфликтов и ограниченным повтором всей операции. Конкретные коды ошибок
Prisma проверяются по выбранной версии и не становятся частью публичного API дневника.

## Проверка на T002–T004

| Сценарий | Как выбранный вариант его поддерживает |
|---|---|
| Первый ручной план без МПВ | React хранит незавершённый ввод отдельно; Nest принимает структурный план и полный факт без обязательной подсказки |
| Первый факт и фиксация всей тренировки | Одна транзакция PostgreSQL проверяет редакцию и сохраняет фиксацию, условия, факт и согласованный результат |
| Разминка до основной части | Отдельное состояние фиксации в той же БД; UI не превращает отметку разминки в начало основной части |
| Закрытая вкладка в конце недели | Обработчик внутри Nest и приведение перед операциями используют дату БД и общий порядок блокировок |
| Прерывание | Одна транзакция сохраняет дату, оставшийся план, отмену будущих недель и итоги; повтор не меняет дату |
| Исправление проходки и связи | Прикладной код пересчитывает затронутые истории полностью под блокировкой владельца; ORM сохраняет результат, но не определяет доменную хронологию |
| Потеря ответа и конкурентный запрос | Ключ операции, уникальность квитанции и проверка редакции дополняют транзакции Prisma; подробный протокол — T007 |

Сценарии сверены с [моделью](./manual-plan-and-fact.md), [календарём](./calendar-and-interruption.md)
и [пересчётом](./history-recalculation.md). Реализованный тест на конкурентную первую
отметку, откат и повтор потребуется в E005 и функциональных эпиках; сейчас проверяется проект.

## Мобильный ввод, доступ и эксплуатация

UI использует карточки упражнений и вертикальные списки подходов. E002 проверяет нотацию,
экранную клавиатуру, сохранение неполного текста, одно касание и русские сообщения.
Минимумы браузеров проверяются по выбранным версиям Tailwind и Ant; нельзя обещать
поддержку старого Safari по одному факту использования React.

Яндекс, VK ID и почта остаются обязательными способами входа. Статическая SPA не содержит
секретов провайдеров, а Nest управляет сессией; подробный проект принадлежит T006.
Сессии и ключи повторов хранятся в PostgreSQL, отдельный Redis не требуется.

Воспроизводимый запуск описывается для доступного владельцу Docker Compose. Тестовые
и рабочие данные разделяются Compose-проектами, томами, конфигурацией и секретами.
На одном физическом сервере это разделение не обещает независимость от его отказа.
Прямые ссылки SPA обслуживаются статикой, `/api` не получает HTML-заглушку.

Бюджет и поставщик сервера определяются в E003; платные внешние услуги не заказываются.
По указанию владельца система бэкапов сейчас не проектируется. Это ограничение объёма
E001 не отменяет приёмку эксплуатации до выпуска. Проект не обещает отказоустойчивость
одного сервера или гарантированное восстановление без соответствующей проверки.

## Проверка критериев T005

Сравнение альтернатив находится в ADR и исследовании; таблица сценариев проверяет
пригодность стека для модели и операций. Ответственность технологий и размещение
заданы конкретно, источники первичные. Выбор следует прямому условному поручению владельца:
NestJS пригоден, поэтому выбран с Prisma. Проверка типов и тесты приложения неприменимы
к документации; код, зависимости и сборочная конфигурация отсутствуют.
