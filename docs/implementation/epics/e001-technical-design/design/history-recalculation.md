# Исправления и пересчёт истории

Проектный результат [E001-T004](../tasks/t004-history-recalculation.md).
Исправление меняет источник вычислений и согласованные результаты, сохраняя исходный
план и условия, которые не были явно исправлены. Это проект операций монолита с
одной PostgreSQL; приложение, миграции и инфраструктура не создаются.

## Источники и производные результаты

Источники: зафиксированные планы и разминка, целостные пары факта подходов, фактические
даты, сохранённые типы упражнений и признаки подбора веса, замены, облегчённые выполнения,
записи пересмотров МПВ, принадлежность источников через связи упражнений и сохранённые
условия циклов. Запись всегда содержит исходно выбранное личное или системное упражнение.
Текущее название общей истории не заменяет этот идентификатор.

| Порядок | Вычисление | Зависимости и ограничение |
|---|---|---|
| 1 | Определить состав затронутых историй | Исходные идентификаторы и текущие подтверждённые связи; без переноса самих фактов |
| 2 | Исходы подходов и полнота упражнений/тренировок | Зафиксированный план, исправленный факт, фактическая дата и явные замены; роль не определяется заново по поднятому весу |
| 3 | Состояния календарных тренировок и показатели соблюдения | Полнота, наличие факта в своей неделе, отменённые недели; разминка не закрывает регулярность |
| 4 | Допустимые результаты проходок | Только завершённые развивающие циклы; рабочие подходы основных упражнений с положительными повторениями и датой внутри проходки; без обеих сторон замены и облегчённого выполнения |
| 5 | Хронология МПВ | Результаты проходок и действующие исправленные пересмотры; подбор допускает первый МПВ, но не повышение существующего |
| 6 | Динамика и зависимые подсказки | Исправленный МПВ и отдельные допустимые рабочие выполнения; исключения по их сохранённым условиям |
| 7 | Незакрытая серия подбора, предложения типа прибавки, индикатор разминки | Соответствующие исходные данные и правила серий; уже совершённые переключения не отменяются |

Регулярность учитывает любой отмеченный подход с датой в своей неделе, даже провалённую
попытку. Точность учитывает только участвующие рабочие подходы основных упражнений,
включая неотмеченные в знаменателе; замены и облегчённые выполнения исключаются
из обоих количеств. Подбор сам по себе точность не исключает. Целостность проверяет
непустоту и проведение всех тренировок каждой недели; у прерванного цикла всегда «нет».
Индикатор разминки независимо пересчитывается по сохранённому комплексу и наличию
любого факта; снятие всех подходов исключает тренировку из его знаменателя.

Рабочий вес выполнения — наибольший успешный фактический вес плановых рабочих подходов
одного упражнения в тренировке. Нулевые повторения не дают поднятого веса.
Несколько выполнений в неделе показываются отдельно, без замены средним значением.
Облегчённое выполнение, замена, вспомогательный тип и сохранённый подбор исключают
выполнение из динамики по бизнес-правилам. Зал только подписывает точку.

## Хронология МПВ и сохранение намерения

Пересчёт истории одного упражнения начинается с первого сохранившегося источника
либо с проверенной опоры перед самым ранним изменённым источником. Для первой версии
выбран полный пересчёт затронутой истории: он проще проверки частичных зависимостей
и не требует отдельной инфраструктуры. Циклы рассматриваются по датам их окончания,
пересмотры — по их действующему порядку; в интервалах между пересмотрами выбирается
лучший допустимый результат проходки. Пересмотр устанавливает новую опору для
последующих результатов, даже если она ниже более ранней проходки.

Для записей с одинаковой датой сохраняется устойчивый порядок исходных действий;
порядок не зависит от времени исправления. Если объединение историй обнаружило два
разных пересмотра одной даты без определимого порядка, подтверждение связи требует
выбора атлетом, какой существующий пересмотр последний. Сервер не придумывает
порядок и не предлагает в этой операции ввести новый МПВ. Для серии подбора при
одинаковой фактической дате используется порядок тренировок в плане по [max-and-progression](../../../../requirements/max-and-progression/index.md), R17.

Ошибочный результат проходки и ошибочная запись пересмотра сохраняются в истории
исправлений с указанием заменившего их источника. Актуальные МПВ и графики используют
правильный источник; исправление не показывается новым достижением. Исправление
существующего пересмотра не создаёт первый МПВ вручную и не является обычным новым
пересмотром. Если единственная допустимая проходка была ошибочной, МПВ может исчезнуть.
Последующие существующие пересмотры обрабатываются по [max-and-progression](../../../../requirements/max-and-progression/index.md), R6.2, а не отменяются автоматически.

Уже созданные циклы сохраняют исходные МПВ, согласованные цели и введённый план.
Пересчёт отмечает недостоверность текущей опоры и показывает правильный МПВ;
подстановка подсказки от недостоверной опоры недоступна. Атлет может отдельным
действием принять исправленную опору и согласовать цель ещё не прошедших недель.
Для этого условия предписаний сохраняются с областью действия по неделям:
прошедшие недели продолжают использовать прежнюю опору. Принятие не меняет веса
введённого плана и не открывает зафиксированную тренировку. Править план можно
только по обычным границам [week-planning](../../../../requirements/week-planning/index.md), R19.1–R19.5.
Если правильного МПВ нет, числовые предписания не предлагаются; ручной путь сохраняется.

## Настройка сегодня и исправление истории

| Действие | Где меняет данные | Что не меняется автоматически |
|---|---|---|
| Обычная смена типа упражнения | Текущее упражнение у атлета и ещё не зафиксированные планы | Тип в зафиксированном плане, прошлые показатели и допустимость проходок |
| Обычное включение/снятие подбора | Следующие и ещё не начатые выполнения | Условия уже начатого выполнения, даже внутри той же тренировки |
| Смена типа/величины прибавки | Настройка для следующего развивающего цикла | Сохранённая цель и план текущего цикла |
| Явное исправление ошибочного типа или подбора конкретного выполнения | Адресно выбранные исторические условия и запись их исправления | Состав, порядок, роли, веса и повторения плана |
| Исправление факта/даты/пересмотра | Конкретный источник и зависящие от него результаты | Исходное намерение и уже согласованные условия других циклов |

Команда исторического исправления указывает конкретное выполнение, исправляемое
условие, новое значение и ожидаемую редакцию. Сервер сохраняет исходное значение
и отдельное исправление; расчёты используют его действующее значение. Обычная
настройка не превращается в массовое исправление прошлого.
При поздней первой записи подбор определяется на действительную дату, тип —
из зафиксированного плана. Исправление фактической даты требует проверить применимость
сохранённого подбора к правильной дате; необходимое исправление исторического условия
показывается и подтверждается явно, а не заменяется сегодняшней настройкой.

Исправление факта пересчитывает незакрытую серию подбора, но не отменяет уже совершённое
ручное или автоматическое переключение. Для предложений типа прибавки заново проверяются
условия сопоставимости трёх циклов; исправление не считается новым циклом и не обходит
срок повторного предложения после отказа.

## Переустановка связи упражнения

Предварительный просмотр строится из одной редакции источников и показывает переносимые
и остающиеся выполнения, МПВ и получающиеся текущие настройки. Он не изменяет данные.
Подтверждение содержит редакцию просмотра и явные решения конфликтующих настроек.
Если до подтверждения изменился факт, связь или пересмотр, результат просмотра устарел:
сервер требует новый просмотр, сохраняя введённые решения для повторной проверки.

При подтверждении сервер проверяет одинаковую единицу веса, меняет только связь личного
упражнения и пересчитывает обе исходные и результирующие истории. Прямые записи системного
упражнения и записи других личных упражнений не переезжают. Пересмотр МПВ принадлежит
исходно выбранному упражнению и перемещается только вместе с его историей.
Тип и подбор в прежних выполнениях не заменяются текущими выбранными настройками.
Текущие общие настройки при разделении не откатываются: они предлагаются обеим историям;
конфликты при новом объединении разрешает атлет. Счётчик подбора начинается заново
у историй, состав которых изменился. План, факт, даты и единицы прошлых выполнений
не переписываются. Уже созданные циклы получают предупреждение об изменённой опоре
по тем же правилам, что при исправлении проходки.

## Граница согласованного изменения и сбой

Каждая команда исправления проходит через проверку сессии и владельца из [T006](../tasks/t006-access-and-trust.md),
проверку допустимой фактической даты и календарное приведение из
[T003](./calendar-and-interruption.md). Для монолита выбирается одна транзакция PostgreSQL
на команду источника и весь необходимый пересчёт этого владельца; результат не
публикуется частями. Поддержка транзакций, блокировок и обработки конфликтов подтверждена
в [технической основе T005](./technology-stack.md) и [исследовании](./technology-research.md).

Порядок действий:

1. Получить блокировку владельца в том же порядке, что календарный обработчик,
   привести дневник к текущей дате и проверить ожидаемую редакцию.
2. Проверить команду и неизменность области предварительного просмотра, если он нужен.
   Снятие факта удаляет действующую пару значений, а не плановый подход.
3. Сохранить исправление источника с устойчивым идентификатором операции и ссылкой
   на прежнюю редакцию. Для источников МПВ сохранять записи исправления по [max-and-progression](../../../../requirements/max-and-progression/index.md), R5.
4. Пересчитать все затронутые истории и результаты в приведённом выше порядке.
   При связи обрабатывать обе истории в одной транзакции.
5. Сохранить новые редакции источников и результатов, предупреждения об опоре и
   результат операции. Подтвердить транзакцию и только после этого вернуть успех.

Все операции изменения дневника, чтение для предварительного просмотра и календарь
соблюдают общий протокол блокировок. Чтение результата использует согласованный снимок
БД, поэтому не смешивает старые и новые производные данные. Разные атлеты не блокируют
друг друга; общий системный справочник от личного пересчёта не меняется.
Конкурентное исправление одной редакции получает конфликт, а не стирает предыдущее.
При временном конфликте транзакции сервер может повторить её целиком с повторной
проверкой времени и редакции; логическая команда не получает новый идентификатор.

Сбой до подтверждения откатывает источник, историю исправления и все результаты вместе.
Повтор начинает с последнего согласованного состояния. Сбой после подтверждения,
когда ответ потерян, обрабатывается по сохранённому идентификатору операции: возвращается
исходный результат без второй записи исправления или повторного достижения; детали
протокола повторов относятся к [T007](../tasks/t007-input-preservation.md). Технические ошибки содержат код и идентификатор
операции без факта, нотации, комментариев, секретов и содержимого дневника.

Восстановление здесь означает повтор согласованной операции после сбоя. Проектирование
резервных копий по указанию владельца в текущую работу не входит.

## Проверочные примеры

| Исходные данные | Исправление | Ожидаемый результат |
|---|---|---|
| Первый завершённый развивающий цикл дал 100 кг; второй дал 110 кг; третий — 105 кг, подбор снят. Третий создан от 110 с целью 115; активный четвёртый — от 110 с целью 115 | Факт второго исправлен с 110×1 на 90×1 | После второй проходки МПВ 100, после третьей 105; ошибочные 110 не остаются действующей опорой. У третьего и четвёртого сохраняются исходные 110, цели 115 и введённые планы; четвёртый получает предупреждение, подсказка от 110 недоступна для подстановки до явного принятия правильной опоры |
| Единственный источник МПВ — первый завершённый цикл с 100×1 | Факт исправлен на 100×0 | Провалённая попытка остаётся в истории, МПВ исчезает, новый цикл не получает числовую опору; это исправление, не спортивное понижение |
| Проходка 100; затем пересмотр 80; затем допустимая проходка 85 | Ранние 100 исправлены на 70 | Последующий пересмотр остаётся опорой 80, действующий МПВ после проходки — 85 |
| Та же история; в существующем пересмотре 80 была опечатка | Адресно исправлен пересмотр на 75 | Запись 80 остаётся в истории исправлений; после пересмотра опора 75, после проходки МПВ 85; первый МПВ вручную не создаётся |
| Все рабочие подходы тренировки отмечены; план фиксирован, непустая разминка выполнена | Сняты все факты подходов | План остаётся фиксированным; регулярность и точность пересчитаны, тренировка после своей недели пропущена; из знаменателя индикатора разминки исключена |
| В исходном упражнении один факт, план фиксирован | Поздно внесена явная замена с отдельно введёнными планом и фактом заменяющего упражнения | Исходный план и факт сохранены под исходным упражнением; обе стороны исключены из точности, динамики и МПВ. Обычные незапланированные подходы не добавлены |
| Тип при фиксации — основное, подбор при первом факте — снят | Сегодня тип изменён на вспомогательный, подбор включён | Прошлые результаты прежние; текущий МПВ скрыт во вспомогательном типе, его история сохраняется |
| В прошлом ошибочно сохранён основной тип, фактически упражнение было вспомогательным | Явно исправлен тип выбранного выполнения | Его рабочие подходы исключены из точности, динамики и источников МПВ; состав и значения плана остаются |
| Личное Л связано с С1: проходки Л — 60 и 70; прямые С1 — 50 и 55; С2 пока без источников | Л переустановлено на С2 после просмотра | У С1 МПВ 55, у С2 — 70; источники Л, включая пересмотры, следуют за Л; прямые С1 остаются; исторические условия неизменны |
| У Л есть поздний пересмотр 45, у С2 более ранняя проходка 80; единицы одинаковы | Л объединено с С2 | МПВ после позднего пересмотра 45, ранние 80 его не отменяют; конфликт текущих настроек решает атлет |
| Цикл прерван во вторую неделю; факт подхода записан поздно с датой до прерывания в своей неделе | Исправлен вес или дописан допустимый факт существующего подхода | Регулярность/точность уточняются по начавшимся неделям; целостность «нет», состояние «прерван», МПВ этим циклом не обновляется |
| Тот же прерванный цикл, ранее допустимый факт есть | Дата исправляется на день после прерывания | Команда отклонена, прежний факт сохраняется; неудачная правка остаётся черновиком |
| Переустановка связи подготовлена по редакции 8; параллельно исправлен факт, получена редакция 9 | Подтверждение просмотра редакции 8 | Конфликт, связь не меняется; новый просмотр использует исправленный источник |
| Исправление затрагивает факт, МПВ и две истории | Сбой между расчётом историй | Вся транзакция откатывается; повтор даёт такой же результат, как одна успешная команда |
| Исправление подтверждено, ответ потерян | Повтор с тем же идентификатором | Возвращается исходное подтверждение; второй записи исправления и второго достижения нет |

Поздняя замена требует допустимую фактическую дату и сохраняет исходное намерение
по [week-planning](../../../../requirements/week-planning/index.md), R19.4; факт сам не переносится на заменяющие подходы. Предыдущее ошибочное выполнение
исходного упражнения исправляется отдельным явным действием атлета.

| План при проходке, снятии отметок и замене | Первые примеры и сохранение обеих сторон поздней замены |

| Прерванный цикл | Допустимая поздняя дата уточняет показатели, не меняя прерывание и МПВ; недопустимая правка сохраняет старый факт |

Проверены приведённые сценарии и ссылки на бизнес-правила. Код приложения и тестовый
набор отсутствуют по границам задачи; проверки типов и запуск тестов неприменимы.
Для реализации таблица задаёт проверки пересчёта с управляемым временем, сохранёнными
редакциями и сбоями до/после подтверждения.
