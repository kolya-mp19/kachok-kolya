# E001. Архитектура, технологии и данные

**Шаг:** S01 из [общего плана](../../README.md).

**Документ:** [PRD](./prd.md). Статус эпика ведётся только в
[реестре эпиков](../README.md).

## Текущая точка

- Проектные решения и их проверки собраны в [передаче E001](./design/design-handoff.md).
- Активной задачи внутри E001 нет; все результаты переданы в PRD зависимых эпиков.
- Выбраны TypeScript, React SPA/Vite, Ant Design, Tailwind CSS, NestJS, Prisma и PostgreSQL;
  размещение — один сервер Docker Compose. Приняты [ADR-0020](../../../architecture/adr/ADR-0020-javascript-modular-monolith.md)
  и [ADR-0021](../../../architecture/adr/ADR-0021-durable-drafts-and-operation-receipts.md).
- Следующее действие — подготовить собственные результаты E002 и E003 по переданным входам;
  завершение технического проекта не завершает S01 и не начинает создание приложения.
- Система бэкапов по указанию владельца сейчас не проектируется; будущие условия [E003](../e003-release-design/prd.md) и [E029](../e029-operational-readiness/prd.md) сохраняются.

## Зависимости и результат

Предыдущих эпиков нет. Входные ограничения — [бизнес-спеки](../../../requirements/README.md),
[принципы](../../../principles.md), [карта контекстов](../../../../CONTEXT-MAP.md)
и [принятые ADR](../../../architecture/adr/README.md).

Результат эпика — согласованный проект архитектуры, технологий, хранения и сохранности
ввода, позволяющий начать S02. Это проектирование, а не создание приложения. Выбор стека
согласуется с владельцем продукта до создания проекта или установки зависимостей,
после чего записывается в ADR. Выбранные решения
должны быть перенесены в зависимые PRD до их разбиения на задачи реализации.

Мобильный опыт проектируется в [E002](../e002-mobile-experience/README.md),
условия выпуска — в [E003](../e003-release-design/README.md).
