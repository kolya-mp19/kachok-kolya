# Спеки фич

Бизнес-документация каждой фичи: зачем она нужна, кому, по каким правилам работает и где проходят
её границы. Отвечает на **что** и **почему**; на **как** отвечает PRD, составляемый на её основе.

Каждая фича — папка с `index.md`. Каркасы документов — в [_templates](./_templates/).

Спеки описывают только текущее решение, без версий и истории правок. Нерешённые вопросы живут
не в спеке, а в `open-questions.md` рядом с ней — в спеке остаётся только маркер `⚠XXX-Qn`.
Эти правила и правила ссылок между документами — в [../README.md](../README.md).
Термины — в [глоссарии дневника](../domain/training-log/CONTEXT.md) и
[глоссарии калькулятора](../domain/calculator/CONTEXT.md), решения — в [ADR](../architecture/adr/README.md).

## Порядок реализации

Технически обязательный минимум, ниже которого продукт не работает:

```
Справочник упражнений → МПВ → Цикл → Планирование недели → Разминка → Выполнение тренировки
```

Регистрация нужна раньше всего перечисленного. Динамика прогресса имеет смысл только когда
накопились данные хотя бы за один завершённый цикл.
Калькулятор ни от чего не зависит и может быть сделан первым — он и задуман как точка входа
в продукт.
