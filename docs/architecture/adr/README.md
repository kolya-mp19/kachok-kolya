# ADR — записи о принятых решениях

Решение попадает сюда, когда верны **все три** условия:

1. **Трудно обратить** — цена смены мнения потом ощутима.
2. **Неочевидно без контекста** — будущий читатель спросит «почему это сделано так?».
3. **Был реальный выбор** — существовали альтернативы, и мы выбрали одну по конкретным причинам.

Если хотя бы одно не выполняется, ADR не пишется: обратимое решение просто обратят, очевидное
никого не удивит, а безальтернативное нечего записывать.

На этом этапе фиксируются **только продуктовые и доменные решения**. Технологические
(база данных, ORM, хостинг, схема аутентификации) будут записаны, когда действительно будут
приняты — вместе с PRD, а не задним числом.

| [0015](./ADR-0015-gym-does-not-affect-max.md) | Зал не влияет на МПВ и подсказки; в аналитике только отмечается | Залы, МПВ, аналитика |
| [0016](./ADR-0016-login-providers.md) | Вход через Яндекс и ВКонтакте; почта с паролем — обязательный запасной способ | Регистрация и вход |

Нумерация сквозная, по возрастанию, без пропусков.

**ADR описывает действующее решение.** Когда решение пересматривается, ADR правится на месте,
а прежний вариант, если он был реальной альтернативой, переезжает в «Считанные альтернативы»
с причиной отказа. Когда ADR теряет смысл целиком, он удаляется, а следующие перенумеровываются
вместе со ссылками на них. История правок живёт в git.
