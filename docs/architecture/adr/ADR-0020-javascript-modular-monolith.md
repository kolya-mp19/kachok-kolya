# TypeScript, NestJS и статический React с PostgreSQL и Prisma

**Статус:** Принят

## Контекст

Владелец выбрал экосистему JavaScript, готовый UI, Tailwind CSS, монолит с PostgreSQL
и размещение на одном сервере через Docker Compose. Серверный рендеринг продукту
не требуется. Владелец поручил оценить NestJS с React SPA и использовать Prisma ORM,
если NestJS подходит; TypeScript и сопровождение по инструкции подтверждены отдельно.

Дневник требует согласованной фиксации плана, факта, календаря и пересчёта истории.
Калькулятор работает только в памяти вкладки. Поисковая индексация личного дневника
не является требованием. Сравнение возможностей и первичные источники приведены
в [исследовании](../../implementation/epics/e001-technical-design/design/technology-research.md).

## Решение

Выбран TypeScript в экосистеме JavaScript: NestJS как модульный монолит на Node.js,
React SPA со сборкой Vite, Ant Design для готовых элементов управления, Tailwind CSS
для компоновки. Постоянное хранилище — одна PostgreSQL, доступ и миграции — Prisma ORM.
Прикладные модули и транзакции определяются моделью дневника, а не структурой ORM.

React выпускается статическими файлами; сервер Next.js и SSR не требуются. Калькулятор
имеет отдельную клиентскую точку входа без загрузки сессии и зависимостей дневника.
Серверная авторизация, календарь и пересчёты принадлежат NestJS. Наличие статической
страницы не означает возможность вести дневник без сервера.

Текущая цель — готовое локальное приложение без внешних интеграций и выпуска.
Локальный запуск не требует DNS/TLS или удалённого сервера; React и API используют
один localhost origin через локальный proxy. Для регистрации, подтверждения почты
и восстановления пароля SMTP направлен в Mailpit в Docker с локальным веб-интерфейсом.
Яндекс/VK и внешний почтовый сервис отложены. Локальный профиль сессии описан
в [границах доступа](../../implementation/epics/e001-technical-design/design/access-and-trust.md#локальный-профиль).

Для отложенного удалённого этапа один Compose-проект размещает HTTPS reverse proxy со статикой, NestJS и PostgreSQL
на одном сервере. Публичны HTTPS и статика, API доступно через тот же origin по `/api`;
PostgreSQL доступна только во внутренней сети. Данные БД живут в постоянном томе.
Redis, отдельная очередь и облачный ORM-сервис не являются обязательными компонентами.
Поставщик сервера и бюджет относятся к E003; система бэкапов по указанию владельца
не проектируется в текущей работе. Постоянный том не считается резервной копией.

Выбираются поддерживаемые стабильные версии с совместимыми Node.js, React и Prisma;
в [E004](../../implementation/epics/e004-project-foundation/prd.md) и [E005](../../implementation/epics/e005-storage-foundation/prd.md) фиксируются версии и lockfile. Выпуск не использует RC только потому,
что на него указывает `latest` или пример документации. API транзакций и миграций
проверяется по документации именно выбранной версии до создания проекта.

## Считанные альтернативы

- **Next.js с SSR и NestJS.** Даёт серверное получение данных и рендеринг, но добавляет
  второй серверный слой без требуемой пользы для личного дневника.
- **Next.js со статическим экспортом.** Возможен без сервера Next, но ограничения
  экспорта и дополнительная модель маршрутов не упрощают выбранную границу SPA/API.
- **React и Express/Fastify без NestJS.** Меньше служебного кода на старте, но соглашения
  о модулях, доступе, валидации и обработке ошибок пришлось бы поддерживать самостоятельно.
  Связанные операции дневника оправдывают соглашения NestJS.
- **Чистый JavaScript без TypeScript.** Соответствует исполняемому стеку, но слабее
  поддерживает различение контрактов плана, факта и условий. Цена TypeScript — компиляция
  и проверка типов; она приемлема владельцу и не заменяет проверку входов на сервере.
- **Самописные элементы UI.** Увеличивают объём работы по полям, фокусу и ошибкам.
  Ant Design сокращает его, но мобильные сценарии всё равно проверяются в E002.

## Последствия и проверка

Две сборки SPA/API и организация маршрутов, загрузки данных и ошибок — явная цена решения.
NestJS и Prisma не реализуют доменные правила автоматически. Транзакция объединяет
фиксацию, факт, производные результаты и подтверждение операции. Конкурирующие команды
используют единый порядок блокировок владельца; отказ сериализации повторяет всю
транзакцию ограниченное число раз. Внешние вызовы не удерживают транзакцию БД.

Вес передаётся десятичной строкой и сохраняется точным десятичным типом; миграции
проверяются на отдельной БД и применяются отдельным шагом выпуска. Ant Design и Tailwind
используют заданные слои CSS; тема компонентов настраивается токенами. Мобильный UI —
карточки и компактные формы, а не обязательная широкая таблица.
