# Разбиение E002–E030 для согласования

Предложены 116 задач для 29 эпиков. Это черновик шага согласования навыка `to-tickets`,
а не опубликованные задачи. Согласованное разбиение E001 не меняется.

Для каждой задачи ниже указаны результат и блокеры. Подробные критерии готовности,
проверки и покрытие приёмки PRD находятся в трёх предложениях:

- [E002–E010: 34 задачи](./e002-e010-proposal.md).
- [E011–E020: 39 задач](./e011-e020-proposal.md).
- [E021–E030: 43 задачи](./e021-e030-proposal.md).

## Условия использования

E002 и E003 продолжают проектирование S01. Они обмениваются конкретными входными
ограничениями с E001 без ожидания формального завершения друг друга.
E004–E030 описаны предварительно: до публикации действующих задач реализации
принятые решения S01 должны попасть в зависимые PRD, после чего разбиение сверяется заново.
Значения бюджета, перечень технологий, браузеры и физическая схема здесь не выбраны.

Каждый функциональный срез включает необходимые хранение, защищённые операции, мобильный
интерфейс и проверки своего результата. Для проектирования, основы и эксплуатации
результат проверяется соответствующим сценарием без искусственного добавления предметных экранов.

Короткие ссылки на E### означают нужный результат эпика, описанный в исходном PRD
и подробном предложении; они не означают обязательное завершение всех его задач,
если это не требуется входными условиями. Отсутствие внутренних блокеров не отменяет внешние.

## Важные стыки

- E001-T001 получает ранние ограничения E002/E003, а не готовые проекты интерфейса и выпуска.
- S05 принимает контракт принадлежности истории. Реальные факты, МПВ и графики принимаются в E019–E022/E026 без обратной блокировки E013.
- E016 принимает контракт истории на проверочных источниках; реальную историю подключает E020. Проверка фиксации E016 ждёт конкретную операцию E017, а не завершение всего эпика.
- [PLAN-Q1](../../docs/requirements/week-planning/open-questions.md) блокирует только сравнение отклонений от истории в E016-T005.
- E025 владеет единым контрактом собственного веса, E027 использует его. [PROGRESS-Q1](../../docs/requirements/progress-analytics/open-questions.md) блокирует совпадающие даты в E025-T005/E027-T003, а не базовый ввод на свободную дату.
- E028 и E029 могут идти параллельно на одной идентифицируемой версии; выпуск E030 ждёт актуальных результатов обоих.
- Доступ первого незнакомого атлета требует возврата функции удаления аккаунта в требования и отдельного принятого эпика до открытия такого доступа.

## Проверка предложения

Проверены наличие всех E002–E030, уникальность 116 идентификаторов, существование
относительных ссылок и явный граф блокеров E###-T### вместе с задачами E001:
битых ссылок, неизвестных идентификаторов и циклов не обнаружено.
Условия уровня эпика и поздние интеграции разобраны в подробных предложениях.
Критерии PRD сопоставлены задачам; обозначения К1… используются только локально
для исходных чекбоксов без идентификаторов и не меняют PRD.

## Вопросы для согласования

1. Подходит ли размер задач; где слишком крупно или слишком мелко?
2. Верны ли блокеры: каждый ли действительно необходим для старта?
3. Какие задачи нужно объединить или разделить?

После согласования E002/E003 можно оформить отдельными файлами по структуре
репозитория. Для E004–E030 сначала выполняется сверка с принятыми решениями S01.

   **Результат:** Схемы объясняют, что сохранено, что ожидает подтверждения и как продолжить после потери связи или сессии.

6. **E002-T006 — Согласовать визуальный язык и передать мобильный проект**  
   **Заблокирована:** E002-T002, E002-T003, E002-T004, E002-T005; E003 — целевые браузеры/условия мобильной проверки.
